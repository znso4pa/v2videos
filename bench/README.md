# 性能基线

这个目录放**机器可读的**性能基线，一个文件一台机器。

## 为什么要有它

README / TODO 里那十几张性能表是**手工誊写**的。三个月后没人说得清
`22.33 ms/帧` 还算不算数 —— 因为：

- 不知道它是在哪台机器、哪个 `rustc`、哪个 profile 下量的；
- 不知道量完之后代码又改了多少；
- 改了一版之后，没有人能一眼看出「快了还是慢了」。

基线文件把这三件事钉住：**哪台机器**（文件名 + `# cpu` / `# arch` / `# cores` /
`# rustc`）、**哪份样本**（`# sample.N`）、**每个用例多少毫秒**。

## 怎么生成

```bash
# 一定要 release —— debug 的数字没有意义（差一个数量级）
cargo build --release -p v2v-cli

./target/release/v2v bench \
    --baseline-dir bench/baseline \
    testing/sample.wmv
```

文件名是**机器指纹**（`apple-m3-aarch64-8c-1.98.0.tsv` 这种），由
`v2v_bench::Fingerprint::slug()` 生成。

## 怎么用

```bash
./target/release/v2v bench \
    --check bench/baseline/apple-m3-aarch64-8c-1.98.0.tsv \
    testing/sample.wmv
```

退出码 0 = 没有超过门限的回归；1 = 有。CI 里可以直接当门。

## 门卡什么、提醒什么

| 情况 | 判定 |
|---|---|
| 「我们 / 参考实现」的**比值**恶化 > `--ratio-tolerance`（默认 15%） | **失败** |
| 绝对 `ms/单位` 恶化 > `--abs-tolerance`（默认 30%），且该用例没有参考实现 | 只提醒 |
| 基线里有、这次没跑（用例被删 / 被跳过） | 只提醒 |
| 这次跑了、基线里没有（新用例） | 只提醒 |

**为什么只有比值能当门**：绝对毫秒在 CI runner 上没有意义 —— 同一份代码换台机器
能差 2×，而「我们比 ffmpeg 慢几倍」是稳定的。比值是两个数相除，机器整体快慢、
后台负载、频率漂移大部分会同时作用在分子分母上而抵消。

**为什么绝对量还要留着**：`transcode/mp4` 这类用例没有可信的参考实现（ffmpeg 的
同参数转码口径很难对齐），只有绝对量。它不能当门，但当它涨了 30% 以上，多半是真
出了问题 —— 值得打印一行让人去看。

## 实测噪声（2026-11-04，Apple M3，`sample.wmv`）

同一份代码、同一台机器、相隔 4 分钟连量两次：

| 用例 | per_unit 变化 | 比值变化 |
|---|---|---|
| `decode/video` | −4.8% | **+4.9%** |
| `decode/audio` | −17.8% | **−7.6%** |
| `transcode/mp4` | −4.2% | —（无参考实现） |

读法：**绝对量漂到 18%，比值只漂 5–8%**。这就是「门卡比值」的全部理由 ——
用 30% 的绝对量当门，等于给了一个既会误报又抓不到真问题的阈值。

默认 15% 的比值门限留了 2 倍余量。`decode/audio` 的噪声最大（ffmpeg 那边整轨只要
几十毫秒，3 次取最快仍然抖），必要时 `--ratio-tolerance 25`。

## 基线是在不空的机器上量的怎么办

`v2v bench` 会把当时的三个负载均值记进 `# load` 那一行（`# load 4.09 5.05 5.27`）。
它**不参与比较**，存在的意义只有一个：让这份基线**自证来源** —— 一年后没人说得清
那次为什么偏高，这一行能说清。

负载高时绝对毫秒整体抬升，但比值不受影响（分子分母同时被抬高）。所以：
**比值基线照用，绝对量基线打个折扣看**。

## 它**拒绝**比较的情况

`compare` 会先确认「同一把尺子」，任一项不同就直接报错，不硬着头皮比：

- `profile` 不同（debug 对 release）；
- `arch` / `cores` 不同；
- `sample.N` 不同（换素材了）。

换机器就换一个基线文件 —— 那正是文件名带指纹的原因。

## 已知限制

- **只覆盖 WMV3（VC-1）和 MPEG-1/2**。`v2v bench` 走 `v2v-player`，它只解 WMV3；
  MP43 / WMV1 / WMV2 的样本请用 `crates/msmpeg4/tests/decode_bench.rs`（那份还会
  同时量 ffmpeg 那一侧）。遇到不支持的样本会**明确跳过并说原因**，不会静默少一行。
- **`transcode/mp4` 没有参考实现**：参数固定成 `-g 12` / AAC 128k / 不校验 /
  qscale 6，和 README 那张表同口径。要别的口径就是另一个用例。
- **`--frames` 截断时参考值可能为空**：ffmpeg 的进程启动（20–30 ms）减掉之后如果
  不剩什么，就宁可不给参考，也不给一个假数。
- **短样本的数字不可信**：46 ms 的音频里 30 ms 是启动开销。量性能请用整份样本。

## 谁来跑

- **本地 / 发布前**：人手工跑 `--check`，对着自己机器的基线看有没有退化。
- **CI**：不跑。CI 里没有真样本（版权 + 体积，不入库），而合成样本是 MP43、
  `v2v bench` 打不开。格式与比较逻辑本身是纯函数，由 `crates/v2v-bench` 的单元测试守着。
